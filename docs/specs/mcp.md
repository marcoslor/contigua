Rows marked **target** are the epic #171's contract and are untested until their task in `docs/design/mcp-plan.md` lands; every other row is shipped behaviour as it stands once #162 has merged: refs issued by the Mac as `s<snapshot>e<row>` (S1), `size: [w, h]` the pixel space of `box` and `at` in TOUCH's 0..1 input space (S2), a display's Android windows named `layers`/`l` (S3), and an off-screen node marked `off: true` with no `at` (F9).

## Purpose

An AI agent on this Mac (any MCP client) drives the connected phone through Contigua: it reads the phone's state, opens app windows and links, reads what a window shows as an accessibility tree or a picture, and acts on it with the same input the person's pointer and keyboard send. The surface has no UI of its own beyond Settings › Automation and the menu-bar indicator (PANEL, SET); its users are programs, and the measure of the surface is that a less capable model uses each tool correctly the first time, learning it only from `tools/list` (#171). It sits beside the App Intents surface (INTENTS), whose phone resolution, app matching, link policy and drop limits it reuses.

## User stories

| ID | Priority | Story |
|---|---|---|
| MCP-S1 | P1 | As an agent, I want every answer that reflects the screen to say how fresh it is, so that I never act on a picture that is minutes old (#165). |
| MCP-S2 | P1 | As an agent, I want an action to wait until the screen settles and to show me the screen it left, so that I need no sleeps and no read after every step (#166). |
| MCP-S3 | P1 | As an agent sharing the phone with a person or another agent, I want to know who opened each window and why one vanished, so that I act only on what I mean to (#168). |
| MCP-S4 | P1 | As a harness that shells out to `contigua-mcp`, I want a failure to be a non-zero exit with a sentence, never an empty success (#169). |
| MCP-S5 | P1 | As an agent, I want every refusal to carry a closed code and a sentence that names the next step, so that I can branch on it without parsing prose. |
| MCP-S6 | P2 | As an agent, I want tool descriptions that say what each tool does to the phone, so that I do not guess what `close_window`, `type_text` or `back` will do (#172). |
| MCP-S7 | P2 | As an agent, I want to know whether the phone is locked in a way that matters and what app is in front on it (#167). |
| MCP-S8 | P2 | As an agent, I want to find one app, one heading or one line of text without pulling hundreds of entries (#170). |
| MCP-S10 | P3 | As the maintainer measuring input-to-photon, I want one call that taps and times the picture's change, so that the latency bench drives the real input path (pmaxx). |
| MCP-S11 | P2 | As an agent opening an app, I want its window at the phone's shape and a small stream, so that the app lays out as it does in the person's hand and I am sent no pixels I never see (#175). |
| MCP-S12 | P1 | As the person, I want an agent's typing never to touch my clipboard, so that what I copied stays mine and no app is shown it (#173). |
| MCP-S9 | P1 | As the person, I want automation off until I turn it on, visible while it runs, and absent from every log, so that an agent is never a silent transcript of my phone. |

## States and events

### One act call (Mac, `MCPActMachine`, target)

A pure `(state, event) -> (state, actions)` run once per input-tool, `open_app`, `send_link` and `screenshot` call. `wait`, `observe` and the ref form decide the path; the actions are `sendInput` (reported back as `inputSent`), `waitForClose`, `sendPress`, `sendType`, `sendSettle`, `sendTree`, `answer(...)` and `fail(code)`. A reply carries its `seq`; a reply whose `seq` is not the call's current request is ignored.

| State | Event | Next state | Actions |
|---|---|---|---|
| Queued | `turn` (the window's queue reaches the call), window live | Pressing (ref) / Typing (text) / Sending (point, key, swipe) | `sendPress` / `sendType` / `sendInput` |
| Queued | the client left while queued | Done | none (nothing is sent; MCP-84) |
| Sending | `inputSent` | Sent | (input is on the phone) |
| Sending | `deadline` | Draining | `answer(settle: not_waited, reason: deadline)` (MCP-8) |
| Sending | `windowClosed` · `linkLost` | Draining | as from Sent |
| Sending | `clientGone` | Draining | none |
| Draining | `inputSent` | Done | none (the window's turn is released now, MCP-84) |
| Draining | anything else | Draining | ignored |
| Queued | `turn`, window `opening` or `stalled` | Done | `fail(not_ready)` |
| Queued | `turn`, window gone | Done | `fail(no_window)` with `closed` (MCP-53) |
| Queued | `turn`, phone not online | Done | `fail(phone_offline)` |
| Pressing | `press.ok(box)` | Sent | (input is on the phone) |
| Pressing | `press.failed(gone \| not_visible)` | Done | `fail(stale_ref)` |
| Pressing | `press.failed(off_screen)` | Done | `fail(off_screen)` |
| Pressing | `press.failed(covered)` | Done | `fail(covered)` |
| Typing | `type.ok(entry, via)` | Sent | (the text is in the field; `did` gets `entry`, `via`) |
| Typing | `type.failed(no_field \| not_supported \| failed)` | Done | `fail(code)` (nothing was typed) |
| Sent | (entry) `wait: "settle"` | Settling | `sendSettle` |
| Sent | (entry) `wait: "none"`, `observe` ≠ none | Observing | `sendTree` |
| Sent | (entry) `wait: "none"`, `observe: "none"` | Done | `answer(settle: not_waited)` |
| Settling | `settle.reply(settled \| still_changing(reason))` | Observing / Done | `sendTree` / `answer` (a `still_changing` carries its `reason`, MCP-107) |
| Settling | `settle.failed(not_available \| busy \| failed \| not_connected)` | Observing / Done | settle `unavailable`; `sendTree` / `answer` |
| Settling | `settle.failed(timeout)` (the Mac's own wait ran out) | Observing / Done | settle `still_changing`, `waitedMs` 2000, `reason: deadline` |
| Settling | `settle.failed(no_window \| no_display)` | Closing | `waitForClose(500 ms)` |
| Closing | `windowClosed(reason, by)` | Done | `answer(state: closed, closed, settle: window_closed)` |
| Closing | `closeWaitOver` · `deadline` · `linkLost` | Done | `answer(state: closed, settle: window_closed)` (no reason known) |
| Observing | `tree.reply(ok)` | Done | `answer(tree)` |
| Observing | `tree.failed(code)` | Done | `answer(treeError: code)` |
| Sent · Settling · Observing | `windowClosed(reason, by)` | Done | `answer(state: closed, closed, settle: window_closed)` (MCP-83) |
| Opening · Pressing · Typing | `windowClosed` | Done | `fail(no_window)` (nothing was pressed or typed) |
| Queued · Opening · Pressing · Typing | `linkLost` | Done | `fail(phone_offline)` |
| Sent · Settling · Observing | `linkLost` | Done | `answer(state: offline, settle: interrupted)` |
| any but Done, Sending, Draining | `deadline` (MCP-8) | Done | Queued · Pressing · Typing: `fail(timeout)`; Opening: `answer(state: opening, settle: not_ready)`; Sent: `answer(settle: not_waited, reason: deadline)`; Settling: `answer(settle: still_changing, waitedMs since sendSettle, reason: deadline)`; Observing: `answer(treeError: timeout)` |
| any but Done, Sending, Draining | `clientGone` | Done | none (late replies ignored by `seq`) |
| any but Draining, Done | `otherInput(source)` | same | add `source` to `alsoActed` (MCP-84) |
| Done | any | Done | ignored |

`open_app` and `send_link` enter at **Opening** instead of Queued, with no window turn: `window.opened` and `firstFrame`, in either order (both already known for a raised live window), → Sent (wait settle) or Done; the open bound → Done with `state: opening`, `settle: not_ready` (MCP-41); `error` from the phone → Done with its code. `screenshot` with `wait: "settle"` enters at Sent with no input.

Ignored: a second `settle.reply` (its `seq` is spent), a `tree.reply` before `sendTree`, `otherInput` after Done.

Until T10 ships `ui.press`, a ref tap takes the Sent path: the Mac checks the ref against the window's latest tree (S1, F9), fails `stale_ref` or `off_screen` from Queued, and sends TOUCH at the node's `at`. Until T13 ships `ui.type`, `type_text` takes the Sent path with the `text` message.

### Settling a display (phone, `SettleWatch`, target)

One watch per session (the Mac sends one `ui.*` request at a time, MCP-9). Accessibility events are counted for the display whose window ids the last `windowsOnAllDisplays` read placed on it, and only the content-change types MCP-107 lists. `windowed` is whether the display has had a window: false at the start when the read lists it with none or not at all (it is still opening), true from the start or from its first counted change. A check that finds the display listed with no window answers `loading(true, n)`; one that finds it not listed answers `loading(unlisted, n)`. `checkLoading(n)` reads the display's nodes for a loading signal (MCP-103) off the event thread and comes back as `loading(found, n)`; checks are numbered, and a result whose `n` is not the check in flight (one a change dropped, or one that outlived its watch) is ignored. `loading` in the state is what the last check found, cleared by a counted change; `last` is the last counted change (or the start). One tick is pending at a time: a new one replaces it.

| State | Event | Next state | Actions |
|---|---|---|---|
| Idle | `start(stream, quietMs, timeoutMs, now, windowed)` | Watching(start=now, last=now, events=0, loading=!windowed, windowed) | listen; tick at `now + min(quietMs, timeoutMs)` |
| Idle | `a11yEvent` · `tick` | Idle | ignored |
| Watching | content `a11yEvent` on the display | Watching(last=now, events+1, loading=false, windowed=true) | none |
| Checking | content `a11yEvent` on the display | Watching(last=now, events+1, loading=false, windowed=true) | tick at `min(now + quietMs, start + timeoutMs)` (the check in flight is dropped when it returns) |
| Watching | `a11yEvent` of another type, or on another display | same | ignored |
| Watching | `tick(now)`, `now − start ≥ timeoutMs` | Idle | reply `settled: false`, `reason: loading` if `loading` (the last check found a signal and no change came after it), else `changes`; `waitedMs`, `events` |
| Watching | `tick(now)`, `now − last ≥ quietMs` | Checking(n+1) | `checkLoading(n+1)`; tick at `start + timeoutMs` |
| Watching | `tick(now)`, neither | Watching | tick at `min(last + quietMs, start + timeoutMs)` |
| Watching | `loading(…)` | same | ignored (a check a change dropped) |
| Checking(n) | `loading(false, n)` | Idle | reply `settled: true`, `waitedMs = now − start`, `events` |
| Checking(n) | `loading(true, n)` | Watching(loading=true) | tick at `min(now + quietMs, start + timeoutMs)` |
| Checking(n) | `loading(unlisted, n)`, not `windowed` | Watching(loading=true) | tick at `min(now + quietMs, start + timeoutMs)` (still opening) |
| Checking(n) | `loading(unlisted, n)`, `windowed` | Idle | stop listening; reply `ok: false`, `no_display` |
| Checking(n) | `loading(…, m)`, m ≠ n | same | ignored (a dropped check) |
| Checking | `a11yEvent` of another type, or on another display | same | ignored |
| Checking | `tick(now)`, `now − start ≥ timeoutMs` | Idle | reply `settled: false`, `reason: loading` if `loading` else `changes` |
| Checking | `tick(now)`, `now − start < timeoutMs` | same | none |
| Watching · Checking | `start` (another request) | same | reply the new request `ok: false`, `busy` |
| Watching · Checking | `sessionEnd` | Idle | stop listening; no reply |
| Idle | `loading(…)` | Idle | ignored (a check that outlived its watch) |

| Situation | The surface answers |

## Assumptions

- A client that ignores `structuredContent` reads the same answer from the text block (MCP-5); a client that validates `outputSchema` skips `isError` results, which carry no `structuredContent`.
- ctrl+A (KEYCODE_A with META_CTRL_ON) selects all in a standard `EditText`; a custom field may ignore it, and the returned tree shows that.
- `welcome.device.screen` carries the phone's own screen size in pixels and its dpi; a landscape report is turned portrait for MCP-100.
- macOS 26+ (the app's deployment target); nothing in this surface depends on a later version.

- The phone runs API 34+; `AccessibilityNodeInfo.isHeading` (API 28), `getDrawingOrder` (API 24), `refresh()` and `equals()` by window and source node id are public on that range.
- An accessibility event's display is found through its window id and the last `windowsOnAllDisplays` read; `UiAutomation`'s event listener sees events from every display when connected with `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES` and `windowsOnAllDisplays` flags. To be proved on the emulator before T5 is reviewed.
- A live stream sends a frame at least every 500 ms (repeat-previous) or a `window.still`, so `frame.ageMs` grows past ~1 s only on a paused, stalled or offline window (PROTOCOL.md "Video rules").
- `window.keyframe` on a live stream produces a keyframe within 2 s, the bound `beginFrameSnapshot` already uses.
- Settle measures accessibility quiet, not pixels: a canvas, a video or a map that changes no node settles while it still moves. The tool description says so.
- A loading signal is what MCP-103 names and nothing else: a sheet that fills its chips without a spinner, a custom spinner that is not a `ProgressBar`, or a web page's own spinner (`<progress>`, CSS), is caught only by the quiet period. A View `ProgressBar` sets no `RangeInfo` while indeterminate, and Compose's indeterminate progress indicators report the `ProgressBar` class with no range; to be proved on the emulator in B1.
- `ACTION_SET_TEXT` and `ACTION_SET_SELECTION` through the shell's `UiAutomation` connection reach an `EditText`, a WebView's editable field and a Compose `TextField` on API 34+; a view that draws its own text (a game, a terminal, a canvas editor) offers neither and gets `not_supported` for text outside the key map. Setting text bypasses the input method, so the field's own undo history and any composing span reset; the app's text watchers and length filters still run. To be proved on the emulator in B5.
- A field showing its hint reports the hint as its text and `isShowingHintText` true (`TextView`); a Compose placeholder is a separate text node, not a hint, and reads as text.
- Window ids are stream ids from `WindowManager.allocateStream`: monotonic per app run, reset only by the e2e test hook.

## Non-goals

- A per-app allowlist and confirmations before launch: #111, post-alpha.
- Reading notifications, media sessions or the clipboard; running shell commands; writing files on the Mac.
- Tools for any display other than a window's (the debug route of #143 / #141).
- Splitting an app's merged accessibility text (`68,315 Calculation result`): that is the app's text, passed through.
- Pixel-based settle, OCR, or a diff of two trees: the tree, the settle and the text view replace them.
- Several phones at once from one client.
- Free-form window sizes for an agent: `shape` is an enum, and a new shape is a new value (MCP-100).
- Backward compatibility for old clients during the alpha (design/mcp.md "What breaks").
